# 版本号规范

本项目使用日期版本号，不使用传统的三段式版本号。版本号统一采用：

```text
vYY.MM.DD
```

其中：

- `YY`：年份后两位，例如 2026 年写作 `26`。
- `MM`：两位月份，范围为 `01` 到 `12`。
- `DD`：两位日期，范围为 `01` 到 `31`。
- `v`：固定的小写版本前缀。

示例：

```text
v26.04.01
v26.09.07
```

## 当前版本

当前版本统一记录在仓库根目录的 [`version.json`](../version.json) 中：

```json
{
  "name": "gqy-arch-setup",
  "version": "v26.09.07",
  "versioning": "calendar"
}
```

## 发布规则

- 每次发布使用发布日期作为版本号。
- 同一天发布多个版本时，继续使用当天版本号，并在 CHANGELOG 中记录具体变更。
- 修改功能、修复问题或更新文档，都应在 [`CHANGELOG.md`](../CHANGELOG.md) 中记录。
- 发布前必须同步更新 `version.json`、README 中的当前版本和 CHANGELOG。

## 脚本读取版本

`install.sh` 会从根目录的 `version.json` 读取 `version` 字段，并校验其是否符合 `vYY.MM.DD` 格式。版本文件缺失、字段为空或格式不正确时，脚本会停止执行并报告错误。

CI 工作流也会执行相同的格式校验，避免不符合规范的版本号进入仓库。
